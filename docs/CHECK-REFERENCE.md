# StealthPrivesc check reference

This companion reference maps every catalog check to its scope, underlying collector operations, and an illustrative positive result. It is generated from the check catalog and source collectors; it does not run the scanner.

## Running one check

Use the numeric ID to run one check. The underlying command/API column describes what the collector actually calls; most checks do not start a separate Windows command. The command column gives the exact PowerShell invocation for that ID, including scope opt-ins needed to run it.

```powershell
.\Invoke-StealthPrivesc.ps1 -CheckId 12 -PassThru
```

Add the required scope switch when needed: `-IncludeDomain`, `-IncludeNetwork`, or `-IncludeSensitive`. `-PassThru` returns the structured report. A check needing an opt-in is reported as `Skipped` without that switch. `-CheckId` can also take a comma-separated list.

## Reading the examples

Each row includes a synthetic, abbreviated positive-result report fragment. It demonstrates the report shape and a matching condition; target names, paths, accounts, severity, and exact evidence fields vary by host. Replace the placeholders with host-specific values when comparing a real report. Many inventory checks record informational evidence whenever an object exists; a finding is not automatically a vulnerability. Sensitive values are redacted. The report finding fields are `Severity`, `Target`, `Observation`, `Evidence`, and `Remediation`.
