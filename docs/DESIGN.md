# Design and current limitations

Each input checklist ID is preserved in `data/checks.json`. The dispatcher groups related IDs into collectors and the orchestrator separates implementation coverage from run status. One check failing does not terminate the rest. Expensive service/task/application inventories are cached within a run; incomplete cached evidence propagates to consumers.

Reports are timestamped to avoid replacing earlier assessments. HTML is self-contained, requires no JavaScript or remote assets, and HTML-encodes evidence. JSON schema version 1.0 has host metadata, scope, per-check records and status counts. `-PassThru` returns the same report object; without it, the CLI prints a compact table. The CLI's process exit code indicates a runner failure, not the presence of findings. For automation, inspect `Summary.Error`, per-check `Status` and findings explicitly.

PowerShell 5.1 and 7 differ in JSON-array enumeration; the catalog reader normalizes this behavior. Native structures respect SID-and-attributes alignment on x86/x64, although the tested/recommended execution architecture is x64. Registry/file-system views follow process architecture; use a 64-bit host for system coverage. Explicit WOW6432Node application/COM paths are additionally inspected. No guarantee is made for ARM64 or 32-bit hosts without further validation.

The C# helper only queries tokens, evaluates security descriptors, reads LSA account rights and briefly opens handles with requested rights to test access. It closes all native handles. It does not adjust privileges or modify objects. Native source is compiled in memory with Add-Type; constrained language/application-control policy can prevent this. Startup compilation failures terminate the scan instead of generating misleading results.

Filesystem and registry findings are current-token observations. An administrator scan is useful for configuration visibility but cannot substitute for an assessment using the actual low-privilege token. Service control access is tested through the SCM; file/registry access is evaluated with AccessCheck. Neither test proves exploitability. A service's execution identity, task enablement, recovery triggers, locks, mandatory integrity and application behavior all matter.

Artifact scanning retains no excerpts. File-name and regex searches are heuristic; placeholder values can trigger and unrecognized secrets can be missed. Oversized files are skipped. Credential stores are chiefly inventoried rather than decoded. Wi-Fi XML parsing prohibits DTDs and external entity resolution. Domain queries are explicit, bounded, and separate from local collection. The current LAPS check may read a returned attribute to determine readability but discards the value; it does not decrypt encrypted LAPS material. gMSA password material is never requested.

Remaining engineering work is itemized in COVERAGE.md. Major gaps: maintained CVE/update supersedence data, LOLDrivers matching and CI policy decoding, full task scheduler authorization, complete DLL resolution and privileged-process correlation, native handle/device/namespace checks, effective AD/AD CS permissions, full credential-store exposure analysis, RPC endpoints, and comprehensive EDR/tenant discovery. Partial metadata collectors are not substitutes for those capabilities.

Avoid `Win32_Product` for software inventory because it can initiate installer consistency checks. MSI inspection here opens the cached database in read-only mode and inspects type flags without invoking installation, repair, custom actions or binary extraction.
