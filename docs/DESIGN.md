# Design and assessment limits

The catalog preserves all 148 input IDs and routes each to a collector. Coverage describes implementation; Status describes the run. Completed is not an assertion of safety or exploitability. Access failures, unavailable formats/dependencies and truncation are explicit. A failed check does not stop other checks. Cached inventories replay incomplete-coverage warnings.

Reports use schema 1.5 and tool version 0.2.1, timestamped filenames, escaped HTML and redacted structured evidence. Schema 1.1 added per-check and run-level Diagnostics, RunStatus, PowerShellVersion, and the configured helper timeout while retaining Limitations for compatibility. Schema 1.2 adds SkippedChecks and diagnostic SkipReason, RequiredSwitch and Verification fields. Process exit status describes runner failure, not findings; automation should inspect RunStatus, Summary and per-check Status. Raw secret excerpts, recovered passwords, Wi-Fi keys, managed passwords and authentication tokens are never serialized.

Schema 1.5 also permits additive AssessmentPlan and Footprint metadata. Plan/ Get-AssessmentPlan consume the catalog and source ASTs without running collectors or loading native components. Dependencies are conservative; conditional resources and helper launches are not promised to execute. Footprint counters measure instrumented attempts, cache reuse, wrapped byte reads/writes, explicit DNS/HTTP requests and successfully started direct helpers. They exclude compiler I/O, unwrapped/native/helper-internal operations and implicit resolution. Counters contain no payloads or results. Saved footprints precede their own export; Measure-AssessmentFootprint returns a fresh snapshot including completed export writes in the current module session.

Get-CachedHostInventory extends per-run caching to process snapshots/owners, modules, ACL assessments and non-secret registry policy values. Cached collection limitations and command provenance are replayed. Credential values are not retained in the registry cache. Host facts can change during the scan, including PID reuse; cached facts are assessment evidence, not fresh authorization for an action. Each new run starts with an empty cache. Host-cache insertion is bounded; queries continue uncached after the entry cap.

Invoke-BudgetedCollector establishes a cooperative per-check deadline (default 60 seconds) and a serialized finding-character budget (default 8,388,608). Shared collection checkpoints enforce the deadline and wrapped reads enforce byte limits even when files grow. Existing finding/item limits remain applicable. Native pipe/device/handle calls use a disposable helper so blocking calls can be terminated. Helper process execution, stdin writing and stream draining share a deadline; capture bounds apply separately to stdout/stderr. Cleanup can add a short drain interval. Non-helper CIM/COM/LDAP calls are not universally preemptible. Budget exceptions, including nested native exceptions, preserve findings as Partial and disclose safe diagnostic codes; other checks continue.

Schema 1.3 adds per-check `Verification`: a scope-preserving `RerunCommand`, `WorkingDirectory`, `CollectorStarted`, bounded `Commands`, `OmittedCommandCount`, and `SourceReferences`. Collector entry and shared query attempts are recorded before invocation, including failed attempts; cached inventories replay command provenance as `Reused`. The record is not a full instruction/API trace. Source references are parsed from the loaded collector and project helper ASTs without evaluation and identify implementation expressions that may execute conditionally. They do not capture runtime values. Executable helper arguments are retained only for a fixed allowlist of known queries; other payloads are redacted. No command output is added to verification records.

Schema 1.4 adds `AttackPathAnalysis` with engine version, ranked `Paths`, `RuleCoverage`, and explicit discovery/evidence/output limits. Six rules join SYSTEM service/task inventories to structured access evidence. Exact case-insensitive object/path keys avoid joins based on observation prose, severity alone or filename substrings. Registry provider prefixes are normalized lexically; environment expansion, relative paths, short-name resolution and host lookups are deliberately absent. Duplicate inventory identities are ambiguous and excluded. Existing `Partial`/`Error` findings can support limited-confidence candidates; skipped/unsupported findings cannot. Disabled execution objects are excluded. Elevation is taken from the original report, never the machine running offline analysis.

Path IDs hash the rule, target and controlled resource. Evidence references use the original check ID and zero-based finding index, and HTML links to the corresponding finding. Only allowlisted metadata is copied; arbitrary evidence fields are not duplicated. Candidate status never claims successful exploitation. Corroborated confidence describes agreement of source facts, and prerequisites remain unresolved even when service control rights are present. An engine failure records a run-level Analysis diagnostic, exports the original findings, and sets analysis status to Error without changing collector results. Narrow scans normally have Partial analysis because some rule inputs were not selected. Missing paths never replace individual findings or certify safety.

Schema 1.5 / correlation engine 1.1 adds `PrerequisiteActions` alongside the compatible `Prerequisites` string array. Every prerequisite has a stable ID, unresolved status, one or more manually runnable read-only commands, expected evidence, run context, resolution criteria and remaining uncertainty. Generation consumes report metadata only. Dynamic strings are quoted as PowerShell literals with a single placeholder replacement pass; imported rerun command text is never used as executable material in the new instructions. Focused scanner options accept only in-range integer limits and explicit boolean opt-ins. Native service command arguments additionally reject control characters and double quotes. Search-prefix inspection distinguishes missing files from access/query errors and does not expand paths against the analyst computer. Commands do not run during correlation or mark prerequisites resolved. Older paths without the structured field retain their text-only HTML rendering.

Skip classification is explicit at each gate: disabled scope, absent domain membership, missing RSAT module, or unsupported platform. Default console output always includes skip reasons, independent of the cap on other diagnostics. Retry selectors retain enabled scope switches and add the missing prerequisite switch; they do not change the current run. Unsupported implementations remain separate from Skipped and have no retry selector promising a local fix. SkippedChecks contains selected checks only, with reasons, actions and verification instructions; filter-excluded checks are not mislabeled as skipped.

Diagnostics classify known exception types, categories and numeric codes into plain-language explanations and suggested actions. Ambiguous failures stay explicitly uncertain. Caught errors retain safe metadata through partial results and cached inventories. Exception messages, arbitrary error IDs, target objects, source text and subprocess output are omitted; native codes, helper exit status, timeout and module source file/line remain available. Suggested rerun selectors identify the check; users must retain their original scope and path options. Diagnostics never automatically change permissions, install dependencies, or expand scan scope.

With OutputDirectory, a timestamped text log is created before native initialization and appended as each new diagnostic occurs. JSON and HTML remain end-of-run snapshots. A log write failure is reported and collection continues with in-memory diagnostics. Runner failures preserve their report in the terminating exception's Data['AssessmentReport']; initialized output is exported where possible. An interrupted process can leave only a partial diagnostic log, and failed exports can leave incomplete report files. Module-load failures have standalone recovery guidance because the diagnostic helpers are not yet available.

Native support loads lazily from the selected collector's conservative static dependency set and on-demand helper calls. Source compilation uses Add-Type, subject to Windows policy. With NativeAssemblyDirectory, runtime/architecture-specific assemblies require valid trusted Authenticode signatures; failure never falls back to source compilation. Loading errors affect the current check and other checks continue. Existing types cannot be replaced in the same process. Validation targets PowerShell 5.1/7 under x86/x64 processes on x64 Windows. ARM64 remains outside scope. Registry/filesystem views follow process architecture, with explicit WOW6432Node paths supplementing the selected view. Reports disclose `OperatingSystemArchitecture` and `CollectionView`; x86 scans disclose WOW64 redirection. LocalAccounts uses a native helper where necessary, and Firefox helpers follow NSS PE bitness. See PLATFORMS.md for OS validation targets and evidence requirements.

Permission checks query metadata or briefly open handles. Windows DACL evaluation respects current-token groups, restricted SIDs and denies. AD evaluation uses object-specific AccessCheckByType and principal SELF when available. Mandatory integrity, locks, custom loader flags, service/task triggers and application reachability still affect exploitability.

Potentially blocking pipe/device/handle queries, UWP, Firefox NSS, remote DC registry and CI parsing run in timed helpers. Helpers bound stdout/stderr to eight MiB characters per stream and apply a deadline to both process execution and stream draining. Native Windows PowerShell module paths are prepended when a helper inherits a PowerShell 7 environment. Pipe/device loops have cooperative budgets. Service queries set a CIM operation timeout; service/task caches retain at most MaxItems rows plus an overflow sentinel and replay truncation diagnostics. Other CIM/COM/LDAP calls are not universally wall-time bounded. MaxItems is not a global memory/time budget. The validation runner separately enforces a per-suite timeout.

JSON is written through a temporary sibling file and then replaced. If subsequent HTML export fails, the runner records RunStatus=Failed and attempts a JSON-only recovery write containing the export diagnostic. If that recovery also fails, the log/warning explicitly says an existing JSON file may predate the failure, and the terminating exception still retains AssessmentReport. JSON and HTML are not an atomic pair; interruption may still leave incomplete output.

MSRC snapshot evidence includes selected source months and gaps between them. Gaps, unknown month metadata and stale retained-month retrieval dates produce Partial coverage. Refreshes merge the requested months by default; ReplaceWindowsSnapshot explicitly discards other months. Historical retrieval dates are preserved, so a recent refresh cannot silently make retained records appear current. Domain samples use SampledCoverage diagnostics; current-computer LAPS is a finite query and can complete when all requested attributes are readable.

Credential probes are optional. Native buffers controlled by the implementation are cleared before release. Managed strings returned by Windows/WinRT/XML APIs cannot reliably be wiped, but are never serialized. Firefox uses a publisher-verified installed NSS library in a separate process, with read-only databases and profile module loading disabled. No primary-password cracking or app-bound encryption bypass is attempted.

SQLite connections are read-only and do not copy credential databases into the workspace. Queries have busy, execution and result limits. Session parsers bound input/decompressed sizes; persisted sessions do not establish live browser state. XML DTDs/external entities are prohibited. File traversal skips reparse points, and secret searches retain categories rather than excerpts.

MSRC assessment uses the earliest fixing revision published for an exact Windows product/branch/architecture/role in the selected snapshot. Legacy fixing builds come from Microsoft KB titles when CVRF lacks FixedBuild. Unmatched products are unknown, not patched. Update history does not independently prove supersedence.

CI analysis uses a pinned BSD parser with documented compatibility changes. Kernel signing-scenario references are checked before attributing a deny. Hash/version rules and TBS signer candidates are distinguished. Publisher/EKU/issuer/OEM/exception/signing-time restrictions remain conditional when unresolved. No deny match is never a load-permission result. Unknown future CI extensions are a coverage limit.

Domain queries are opt-in and sampled. Applied GPOs use computer RSoP; unavailable RSoP does not mean no policies. AD CS checks combine publication, enrollment rights, flags/EKUs and issuance controls; CA-side settings can constrain results. Encrypted LAPS attributes remain encrypted. gMSA password-readability requires both domain and sensitive opt-ins. Relay assessment reads one discovered DC's configuration and never performs an authentication relay.

NVD receives package name/version for keyword candidate lookup; exact CPE applicability needs review. Cloud probes use fixed link-local endpoints without proxies/redirects. Optional identity responses are reduced to accessibility/expiration evidence and never used elsewhere. An identity accessible to its own workload is not inherently a vulnerability.

MSI databases open read-only. There are no Win32_Product queries, repair/installation consistency checks or custom-action execution. Static analysis cannot resolve arbitrary runtime MSI properties or prove repair reachability.
